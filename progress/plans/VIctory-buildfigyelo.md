## What is worth trying first?

1. **Look for waiting caused by memory in the local KLBF run.** From the same save, drive a 120-second route that loads textures. Record the median and p95 frame time, the peaks of dedicated and shared GPU memory, Windows' remaining commit and textures that appear late or wrong. Note one cold and three warmed-up runs separately. The local base settings and test scenes are already in the [test order](VIctory-teszteles-es-javitasi-sorrend.md).
2. **cool_fox's first candidate is `ab75ac3`.** When allocatable memory runs out, this change delays retrying a refused GPU pool growth and holds back uploads. In the donor's log the median of the opening save's 120 heavy-draw measurement intervals was 54.3 ms per frame; 39 intervals reached 50 ms per frame or better. The lowest free Windows commit was 1.30 GiB. So on our own 32 GiB machine the change in stutters and any texture faults is especially interesting. [Commit](https://github.com/DoubleGhosty/cool_fox/commit/ab75ac3) · [Measurement conditions](https://github.com/DoubleGhosty/cool_fox/blob/f4b48ad766ddbec1a1867022cd42f7645b0dd55e/docs/bug-journal.md)
3. **Make an A/B version if the same bottleneck shows in KLBF too.** First compare the pool and texture-upload code. If the solution is missing, try it on a separate test branch on this one route, with the same driver and cache state. Besides the p95 improvement, check whether the same textures arrive and how long they stay blurry.

## How can the 21 fps claim be checked?

The card also gives a frame time below 40 ms on AMD. An 18 fps average is about 55.6 ms per frame, 21 fps 47.6 ms per frame. A total frame time below 40 ms would mean more than 25 fps in the same measurement window. First look in the original log for which stretch the 40 ms measures, what time window it covers, and whether the fps counter includes generated frames. For the second start shown in the picture the initial state of the shader and pipeline caches is not given either.

There is already a public profile for a Radeon comparison. DexNom's RayTime README upscales a 2560×1440 internal picture to 3840×2160 on an RX 7900 XTX, with FSR Quality and RT. The author gives about 1.1–1.3 fps in a waterfront scene after warming up. That is an identifiable setting and scene; the link to the video is still open. In our own notes, output and internal resolution get separate fields. [DexNom test profile and result](https://github.com/DexNom/VIctory#fsr-quality-4k-baseline)
