26 November 2026, 21:10 (local time). Previous: [Claude-15](Claude-15-20261126-2105.md). The user's request: a better picture in the boat scene, and to see what the machine can do without the 30 fps cap.

## 1. The 30 fps cap

- **The bundle's own switch:** `VICTORY_FRAME_INTERVAL_MS` (`crates/victory-gpu/src/frame.rs`).
  - `16.667`: 60 fps pacing;
  - `0`: no waiting.
- **The loader passes the same to the game** (`victory_loader::frame_rate`). In the test start's log: `the title's read of its frame rate setting patched … kind=Load rate=60` (2×) and `kind=SimRate rate=60`.
- **The simulation switches to 60 fps pacing too.** According to the bundle's README the game's clock stays right.
- **Test start (75 s):** the main menu's 3D scene runs at 42.8–55.2 fps, 30 before because of the cap.
- **Expected in the game world:** in the 30 fps runs submission preparation (`SUB`) took 26–32 ms and the GPU 22–27 ms a frame. So without the cap about 32–40 fps can be expected in the world, not 60. The run decides.

## 2. Picture quality

| Lever | State |
|---|---|
| **FSR sharpening** | The game's own value in the PC FSR call: `enabled=false sharpness=0.0`. So the picture is made without sharpening, from 1280×720 to 1920×1080. **New** (`crates/victory-hle/src/modules/fidelityfx.rs`): `VICTORY_FSR_SHARPNESS=<0..1>` overrides the SDK's `enableSharpening` and `sharpness` fields in the bridge's own copy. The game's value is logged once. In the test start 0.5 took effect, and the temporal dispatch ran without errors. The bundle's FidelityFX test: 1/1. |
| **Texture cap** | 512 px is needed because of memory (Claude-11). 1024 px as an experimental menu option; the bundle's own rule steps back to 512 above 92% VRAM anyway. |
| **Internal resolution** | In Series S the game renders at 1280×720. Raising it would only be possible with the Series X 4K profile (`-Fsr4K`), but that needs much more GPU and memory because of the 4K output. Not now. |
