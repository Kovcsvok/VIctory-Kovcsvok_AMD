## 2. Where the frame rate went: the boat fix (`CARD_STEPS_LEARN`, avatarmanz PR #434)

| Log, per frame | This run | `221749` and `205130` |
|---|---|---|
| `card steps … submissions waited for a learned page` | **3.8** (2 learned pages) | – (the switch did not exist yet) |
| `submissions sent ahead … settles` | 3.8 | 0.0 (0.3 in one window) |
| `… ms waiting for the card in them` | **16–17 ms** | 0.0 |
| The game's threads wait at the present (`at-present`) | 18–21 ms | about 0 |

**What happens:**
- The game writes to two memory pages (about 8 KB) after it submits.
- Every submission that fills from those pages therefore waits for the card, about 3.8 times a frame.
- **That is the cause of the loss of about 5 fps.** Recording costs nothing (0 dropped frames), and the tree fix (`TWIN_MOVE`) costs nothing either.

**Open question:** which faults does `LEARN` remove here? The PR fixes stretching figures and the boat. The flashing shadows more likely belong to the tree fix, since the trees' shadows go through the same culling shader. The menu-9 live test decides: with `KI: LEARN` ("off") on the HUD, is it back to 28–30 fps, and does any fault come back.

## 3. The clouds

**In five frames around 30.0 s of the video** (a fast-turning camera) the clouds jump back for one frame. The cause cannot be told from this: phase-correlation measurement is unreliable with fast motion.

**Suspicion:** the volumetric clouds use the previous frame's camera matrix for temporal smoothing. If that matrix slips for one frame, the cloud jumps. This needs a recording with a still camera and clouds.

## 5. Pre-building (Codex's plan) in our bundle

**Command:** `victory translate --warm meresek\AGY-eloforditas-shaderek.txt --jobs 4` (2,668 shaders), into the bundle's cache. Because of translator version 2, everything has to be compiled again.

**Important because of the key** (for Antigravity too):
- The shader cache key (`shader_cache.rs::build`) includes:
  - the host settings (wave width, view limit, raw twins, RDNA);
  - `VICTORY_PORT_CBV=1`;
  - and a number of `VICTORY_WAVE_*`-like switches.
- `--warm` does open the card (`precompile` → `host()`), so the wave width and the RDNA setting match.
- **But `VICTORY_PORT_CBV=1` is only taken from the environment.** If `--warm` runs without the game profile's environment, none of its compiles will be found by the game.
- So `scratchpad\elofordit.ps1` starts it with the bundle's full set of settings.

**Result:**
- 2,630 of the 2,668 requested shaders found, all compiled, 0 errors, 136 s on 4 threads.
- In the test start `shaders from the cache … hits=2630 misses=1156`: **exactly all 2,630 pre-built shaders came from the cache, so the key matched.**
- The 1,156 misses come from scenes not on the list.
- `--warm` also accepts any run's `victory.log` as a list (it takes the 16-digit hashes from the lines). So after every normal run it can be extended with that run's own log.

**Kept:** [`tools\elofordit-csomag.ps1`](../tools/elofordit-csomag.ps1) (`-List <list or victory.log> -Jobs 4 -Log <log>`).

**Pipeline book:** `meres-csomag.ps1` now starts with `VICTORY_PIPELINE_BOOK=1`. After the next normal run, `victory warm --used` can pre-compile the pipelines actually used into the driver cache.

## 6. Antigravity's `agy-9070-v2` build: needs fixing before testing

Checked by reading only; I did not touch their tree.

- **`1d68a7b fix(visuals): port TWIN_EXACT …` turns `VICTORY_TWIN_EXACT` on by default** (`crates/victory-gpu/src/descriptor/host.rs:3939`, `is_none_or(|v| v != "0")`).
  - On this card that caused a device loss twice (`0x887A0001`): once on the loading screen, once 13 ms after it was turned on (Claude-21).
  - **With this build the game will probably not even reach the world.**
- **Patch:** `csomag\claude-twin-move-agy.patch` (`087b4e6f…`, local only). It applies to `agy-9070-v2`'s files (only tried with `git apply --check`).
  - `TWIN_EXACT` off by default;
  - `VICTORY_TWIN_MOVE` (moving the twins made in the `ListViews` heap with `move_raw`);
  - a `TWIN_MOVES` counter;
  - both switchable at run time.
- **`CARD_STEPS_LEARN` is in it too:** per section 2 it costs about 5 fps.
