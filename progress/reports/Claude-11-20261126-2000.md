- **Fast:** at least about 3.5 GB of free RAM, the card working at 40–60%, 15–30 fps.

- **19:51:20:** the working set fell from 22.5 to 16.8 GB, free RAM rose from 2.0 to 5.4 GB, and **in the same window** the frame rate jumped from 1.6 to 15.8.

**Leak or too large a demand?**
- Private memory grows in steps at scene changes: 28 → 31 → 33.6 GB.
- By the bundle's own lines it does release texture copies (`148369 let go 14908 MB`).
- So it is more a too-large permanent demand than a classic leak. The bundle's author recommends 64 GB of RAM.

**The biggest items in the bundle's own lines (18:57:5x UTC):**
- the card's own memory 12,396 / 14,222 MB (budget);
- **the part of the PC's memory given to the card: 10,001 MB**, which loads system RAM;
- texture blocks 8,448 MB;
- host copies of textures the game fills 5,680 MB;
- render targets 1,497 MB.

## Step: the bundle's own texture cap

- The bundle already has the counterpart of KLBF's `VICTORY_TEXTURE_MAX_DIM`: `VICTORY_TEXTURE_MAX` (`resource.rs` `over_cap`).
  - **Default:** 1024 px; above 92% of the VRAM budget 512, above 97% 256.
  - **In both runs** VRAM stood at 87% of the budget (12.4 / 14.2 GB), so the cap stayed at 1024 px while 10 GB went into system RAM.
- The launcher now starts with `VICTORY_TEXTURE_MAX=512` by default, like KLBF's `-LowMemory`. No code change or new build needed.
- `Inditas-Csomag.cmd`:
  - `1`: ports + 512 px;
  - `2`: `-Safe` + 512 px;
  - `3`: no cap (the first run's setting).

## What this does not fix

**Picture quality.** In Series S the game's own console FSR4 runs translated (Claude-10). PC FSR in Series S is separate code work, based on KLBF's solution.
