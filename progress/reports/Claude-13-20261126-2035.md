## Pop-in in the log

The bundle's fps line every half minute (`textures picked by index: … uploaded so far, N waiting`):

| | Value |
|---|---|
| Texture slots waiting for upload | **2,200–15,500 throughout**, typically 6,000–11,000 |
| Uploaded in 30 s | 3,000–55,000 textures, 85–1,930 MB (typically about 1 GB) |
| Staging budget per frame (`draw.rs` `staging_budget_per_frame`) | 256 MiB (>12 GiB VRAM). The actual ~1 MB a frame is far below that, so the budget is not the bottleneck. |

**Likely cause:**
- The bundle's `draw.rs` re-checks a texture slot waiting for its memory with a backing-off interval: 1, 2, 4… frames, up to about 4 s.
- The author's measurement in the code (`VICTORY_TEXTURE_LOOK_MS`): "from the last look that found a slot's memory away to its upload, half under 0.5 s but nine in ten under 32 s: the memory had come long before".
- So the texture's data has often already arrived, it just is not uploaded until the next re-check.

**Step:**
- `VICTORY_TEXTURE_LOOK_MS=250`: re-check at least every 250 ms. No code change needed; the switch is in the bundle.
- Cost: more re-checks a frame. Below the 30 fps ceiling there is about 3–7 ms to spare.
