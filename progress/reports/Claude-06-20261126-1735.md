## 1. The change

| Place (`klbf-c1` `xmem.rs`) | What it does |
|---|---|
| `Physical::holes` (534) | Records the placeholders that removing one of our views left behind at exactly the view's size. |
| `map_lean()` (1251) | `VICTORY_MAP_LEAN`: on by default, off with `=0`. Logs its value once on first use. |
| `map()` (1488–1508) | If the place is the view's own placeholder, it maps directly (`MapViewOfFile3`, `MEM_REPLACE_PLACEHOLDER`). If the game changed the placeholder meanwhile and the call therefore fails, the original path runs: split, then map. |
| `unmap()` (1652–1658) | Only a view fully inside the range leaves its own placeholder behind. |
| `LEAN` counters and log line | About every 5 seconds: `views over physical pages over N s (VICTORY_MAP_LEAN=x): A mapped over their own placeholder without a split, B after a split; C found their placeholder changed…`. This confirms which path ran. |
| Tests (2116, 2153) | The donor's content-preservation test (also after placeholders are merged) and a new test that recording and using the placeholder works. |

**With the switch off (`=0`) the code path is the same as the original:** recording and the direct attempt are off; only the counter runs.

KLBF's metrics are kept: `Kernel::begin(0)` measures the whole mapping (split and view together) as before. So the `the kernel's page mapping calls … map … us each` line can be compared across the two paths.
