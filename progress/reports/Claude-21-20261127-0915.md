## 3. Our own tree fix: `VICTORY_TWIN_MOVE`

**What we found** (a counter in `descriptor/host.rs`, `TWIN_MOVES`; a 110 s test, `learn-b`):
- Of the twin views that start at a step below 16 bytes, the program already moved about 90 a frame (`move_raw`: it rewrites the descriptor's address directly).
- But 200–700 stayed null. **Every one of them because it was not made in the thread's own workspace.**
- None had a different descriptor format, so the RX 9070 XT's descriptors are exactly what `move_raw` expects.

**The cause:** the views of the tables of draws and dispatches (`make_listed`, including the tree-culling dispatch's list) are made in the thread's own `ListViews` heap. That heap is just as invisible to the card as the workspace that was already accepted, but `move_raw`'s check did not recognise it.

**The fix:**
- The thread may also move a twin view that lies in its own `ListViews` heap.
- Switch: `VICTORY_TWIN_MOVE`, on by default, switchable at run time.
- PR #437's way (`VICTORY_TWIN_EXACT=1`) stays selectable, but off by default.

**Tests:**

| Test | Result |
|---|---|
| `move-c`, 120 s, default setting | 268–529 such twin views a frame, **all moved, 0 null.** No device removal. **The user saw it on screen: "the trees do not pop".** |
| `ab-proba`, 85 s, live on/off | Off (08:14:11–21): 140–156 null a frame; switched on at 08:14:21, and 0 in the following seconds. No crash. |
