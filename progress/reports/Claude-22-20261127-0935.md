## 1. F9: video recording inside the game (at the user's request)

**Why F9, not F?** F is taken in the game (getting into a vehicle). F3 belongs to the HUD.

**New file:** `crates/victory-gpu/src/record.rs`. Only in the diagnostics build, which the bundle uses.

**How it works:**
1. Every frame, the presented picture (with the HUD and its clock) is copied into one of a ring of 8 read-back buffers.
2. Once the submission with the copy has run (`host::submissions`), a thread of its own hands the picture to the Windows Media Foundation encoder. The encoder makes H.264 at 16 Mbit/s, with the hardware encoder allowed.
3. Every frame goes into the video with the timestamp at which it was presented. So the video holds exactly the frames the window showed, none twice. The Windows recorder, by contrast, wrote the same frame several times when the game was slow.
4. The presenting thread waits neither for the card nor for the encoder. With no free buffer, the frame is left out and counted.
5. The file is a fragmented MP4 where the system supports it, so it plays even if the game ends without F9.

*(Later, Claude-28: Windows' frame readers did refuse such an unclosed file; the recording is now also closed when the window is closed.)*

**Where does the video go?**
- `VICTORY_RECORD_DIR`: `meres-csomag.ps1` gives the run's folder;
- if not given: `recordings`;
- the name: `felvetel-<HHMMSS>-UTC.mp4` ("felvetel" = recording).

**On the HUD:** a red `REC` in the clock's line. The clock's bar is now always as wide as the HUD box.

**Test trigger:** `VICTORY_RECORD_AT=<from>,<to>` seconds. Works as if F9 were pressed, without pressing a key.

**Test** (`rec-a`, 115 s, recording between second 75 and 95):

| | Result |
|---|---|
| Log | `recording (F9) started … 1920x1080 format=28` → `the file is complete frames=469` → `stopped frames=469 dropped=4 seconds=19.9` |
| File | 39.9 MB, 19.9 s, 1920×1080 |
| The picture at second 12 | right orientation and colours; the HUD shows `UTC 08:27:49.581 \| FRAME 1880 \| REC`, `30 FPS` |
| Timing | the recording started at 08:27:37.58; at second 12 the clock shows 08:27:49.58: an exact match |

**Not measured yet:** the cost of recording in a steady scene. The 4 dropped frames were during the slowdown while loading.
