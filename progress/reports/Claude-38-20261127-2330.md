## 6. The user's three picture faults

The user reported three things:
- Jason's shirt looked wrong the whole time: dark with bright specks.
- A dark, half-transparent blob appeared on screen at times.
- In places the ground texture was missing and the ground was black.

**None of these looks new tonight.**
- The kinds and rates of warnings are those of the runs before Claude-34 and Claude-35:

  | Warning | `181452` (before) | `212924` | this run |
  |---|---|---|---|
  | View records found by the fallback | 1,521/min | 1,448/min | 1,559/min |
  | Textures uploaded again | 4.9/min | 20.0/min | 8.5/min |
  | Placed unordered texture views not mirrored | 1.8/min | 7.5/min | 3.3/min |
  | Pipeline methods not implemented | 0.7/min | 2.9/min | 1.2/min |

- No new kind of warning appeared.
- The view fix (Claude-34) changes how buffer views are named. It touches no textures.

**Black ground: most likely the writes through placed unordered texture views, which are dropped.**
- `descriptor/host.rs` 4613–4640 gives each such view a null descriptor, so what a shader writes through it is lost. This is known since Claude-26 and done the same way in every local fork.
- In this run the counter passed 65,536 at 22:14:12 UTC (8,192 at 21:55:47), so about 2,800 such views a minute.
- All 78 that were logged are 2D textures (`resource [3, 9, 0, 0, …]`). Their view words 10 and 11 (the address) are 0, so the code does not know which texture they name. Claude-29 found the same for the lost BC texture writes.
- Textures the title fills on the card (terrain and decal pages, for example) stay empty if their writes are lost.
- To fix it, the texture behind such a view must be found: from how the title builds the view, or from the resource words. That is research, not a quick switch.

**The shirt: most likely the 42 character ray-tracing resolve shaders that the bundle skips.**
- The bundle skips them by default (`-RtFeloldas ki`, `csomag\rt-feloldo-shaderek.txt`, since Claude-24). Run without a scene structure (BVH), they gave blue-purple faces and glowing eyes.
- Skipped, their output is never resolved. Bright specks on dark cloth fit raw, unresolved ray samples.
- Not proven. Two short unattended runs from the same save would settle it: `-RtFeloldas ki` against `be`, each about 4 minutes, comparing the shirt.
- The real fix is real ray tracing, so that the resolve gets valid input. That is Antigravity's native DXR track (Claude-36), at its frame cost.

**The dark blob:** no cause found from the log. The dark triangle at 31.47 s (Claude-18) is an older open fault of the same look.
